## Purpose

This file indexes the plans that implement stria v0.1 and holds the
execution protocol every plan follows. stria is the renamed KaibaViewer
scaffold, turned into a macOS PDF reader with an OCR-indexed SQLite page
store, an agent chat pane and an agent-facing JSON CLI. agent-gateway is the
only AI library, and riela is not used.

Workers do not edit this file. Only the serial reconciliation/finalization
step updates it, for example to move plans to `impl-plans/completed/`.

## Declared-Path Rule (hard)

The session-241 fanout failed with "unsafe fanout change tracking path",
because P05 declared `.build/checkouts/agent-gateway`, a SwiftPM checkout
with a nested `.git`. Every `writePaths`, `sharedPaths`, `sharedPathNotes`
or `trackedPaths` entry in every plan and in the manifest must therefore:

- be a repository-relative source path;
- never be `.build`, anything under `.build/`, `dist/`, `release/`, `tmp/`,
  or any directory that contains a nested `.git`;
- stay small: each file is at most 8 MB and the declared total at most
  64 MB.

The agent-gateway API is taken from
`design-docs/references/agent-gateway-c7f2697.md`. The checkout may be
*read* when needed, but it is never declared. Test PDFs and images are
generated at test time in temp roots and are never committed.

## Common Execution Protocol (all plans)

1. **Read first.** Before starting, read the plan, the design sections it
   cites, `AGENTS.md`, and `.claude/skills/swift-coding-agent/SKILL.md`.
   Write in English only, with no emojis. Keep every Swift file under 1000
   lines.
2. **Intent snapshot is immutable.** Do not edit any section of a plan file
   except its own `## Progress Log`. If the plan looks wrong, record that in
   the Progress Log and follow the design doc.
3. **Fresh read before each edit.** Re-read a file immediately before editing
   it. Never edit from a stale copy.
4. **Hashes.**
   - Before the first edit of each file in your `writePaths`, record
     `shasum -a 256 <file>` (or `absent`) in your Progress Log.
   - After your last edit, record the post-hash.
   - Before final verification, re-hash all your files. If a hash differs
     from your recorded post-hash, another actor changed the file: re-read
     it, re-apply only your intent, and log the drift.
5. **Stay inside your paths.** Never write outside your `writePaths`.
   `sharedPaths` are read-only unless the plan says otherwise. If you need a
   change in another plan's file, record the request in your Progress Log
   for serial reconciliation. Do not make the change yourself.
6. **No git state changes.** Do not run `git add`, `commit`, `mv`, `stash`,
   `checkout`, `reset`, `switch`, `branch`, or `worktree`. Read-only `git
   status`, `git diff` and `git ls-files` are allowed. Move files with plain
   `mv` or `mkdir`. Commits happen in serial finalization.
7. **Dependencies.** Do not run `swift package update`. Do not change
   `Package.swift` or `Package.resolved`. Completed P01 set them, and no
   remaining plan edits them.
8. **Evidence logs.**
   - Run every verification command in the foreground and tee it to
     `tmp/verify/<planId>/<name>.log`, for example
     `mkdir -p tmp/verify/P03 && swift build 2>&1 | tee tmp/verify/P03/build.log; echo "exit=${PIPESTATUS[0]}"`.
   - Record the command, exit code and log path in the Progress Log.
   - An incomplete log is not a pass.
9. **Foreign build failures.** All plans share one module (`StriaCore`), so a
   build can fail because another worker's in-progress file does not compile
   yet.
   - Fix every diagnostic located in your own `writePaths`.
   - If the only diagnostics are in files outside your `writePaths`, re-run
     the build up to 3 more times as other workers finish. If they persist,
     record "blocked by foreign diagnostics: <files>" in the Progress Log and
     stop. Post-join serial verification resolves it.
   - Never edit foreign files to make your build pass.
10. **Lint and size.**
    - Run `swiftlint lint <your swift files>` and fix the findings in your
      files.
    - Check that no file is 1000 lines or longer with
      `wc -l <your swift files>`.
11. **Test suites.** Group tests as `@Suite struct <SuiteName>`, using the
    suite names given in each plan, so that `swift test --filter <SuiteName>`
    selects exactly that plan's tests.
12. **Stub replacement.** `Sources/StriaCLI/main.swift` and
    `Sources/StriaApp/StriaAppMain.swift` are stubs committed by P01. P09
    and P11 replace them. Each has exactly one owner in this manifest.
13. **No real data root.** Tests and manual runs must use temp roots, either
    `TestDataRoot` (from P01) or `STRIA_HOME=$(mktemp -d)`. Nothing may write
    to `~/.local/stria` or into the repository tree, except
    `tmp/verify/<planId>/` logs.
14. **No secrets.** Never print, log, store or commit secret values. Config
    and logs contain environment variable names only.

## Session-245 Stabilization Protocol (all plans; supersedes rules 8 and 9 where they differ)

- **S1. Evidence root.**
  - Write every log to `tmp/stria-v01-session-245/<planId>/`.
  - Run each command in the foreground, for example
    `mkdir -p tmp/stria-v01-session-245/P03 && swift build --build-tests 2>&1 | tee tmp/stria-v01-session-245/P03/build-tests.log; echo "exit=${PIPESTATUS[0]}"`.
  - Record the command, exit code and log path in your Progress Log.
  - `tmp/` is gitignored and is never declared as a plan path.
- **S2. Baseline first (wave-1 plans).**
  - Before your first edit, run `swift build --build-tests` and your
    plan's focused `swift test --filter` command.
  - Save the logs as `baseline-build-tests.log` and `baseline-focused.log`.
- **S3. Red-green evidence.**
  - For every behaviour fix a plan names, run the new or affected test
    before the code change and keep the failing log as
    `red-<task>.log`.
  - Run it again after the change and keep the passing log as
    `green-<task>.log`.
- **S4. Test integrity.**
  - Never delete, skip, disable (`.disabled`, `withKnownIssue`,
    `#if false`) or loosen an existing `#expect` or `#require`. The only
    exception is the one named in the plan (P03-S1).
  - Never change a test's input data to dodge a failure. For example,
    keep "offline text" as it is.
  - Never special-case test values in production code.
  - Before finishing, run
    `git diff 0082491 -- <your test dirs> | grep -E '^-[^-].*#(expect|require)'`
    and paste the output into your Progress Log. It must be empty, or show
    only the named exception.
- **S5. Shared test target.** Every plan compiles into the one
  `StriaCoreTests` target, so a parallel worker's half-finished file can
  break your build.
  - Finish only after `swift build --build-tests` exits 0 with your files.
  - Then re-run your focused tests as the last action of your run
    (`focused-final.log`).
  - If the build fails only in files outside your `writePaths`, do not
    edit them. Wait at least 2 minutes and re-run, up to 3 times.
  - Only then record `blocked by foreign diagnostics: <file:line>` with the
    log path.
  - Never declare blocked on the first failure.
- **S6. Paths.** Never declare or write `.build/`, dependency checkouts,
  `dist/`, `release/`, `tmp/` (except your evidence logs), or any directory
  that contains a nested `.git`. You may read
  `.build/checkouts/agent-gateway` read-only.
- **S7. Progress Log.**
  - Append entries under the `### Session 245` heading of your plan's
    `## Progress Log` only. Earlier entries are history.
  - Each entry lists: pre- and post-hashes (rule 4), the tasks completed,
    the evidence logs with exit codes, and any drift or blocker.

## Post-Join Serial Verification (run by reconciliation/review, not by workers)

Session 245: write logs to `tmp/stria-v01-session-245/join/wave-<n>/` and run
`swift build --build-tests` before `swift test`. Also run these checks after
every wave:

- `grep -rn "launchFailed" Sources` must print nothing (from wave 1 on);
- `grep -rnE '^import (AgentGateway|AgentGatewayAppCore|ACP)$' Sources | grep -v '^Sources/StriaCore/Integration/'`
  must print nothing.

Run this after each wave joins, and once more at the end:

- `swift build 2>&1 | tee tmp/verify/join/build.log` must exit 0.
- `swift test 2>&1 | tee tmp/verify/join/test.log` must exit 0. Tests need no
  network and no credentials.
- `swiftlint 2>&1 | tee tmp/verify/join/lint.log` must exit 0 with no new
  violations.
- `find Sources Tests -name '*.swift' -exec wc -l {} + | awk '$2 != "total" && $1 >= 1000'`
  must print nothing.

- `grep -rIl -i kaiba --exclude-dir=.git --exclude-dir=tmp --exclude-dir=.build --exclude-dir=design-docs --exclude-dir=impl-plans .`
  must print nothing (it stays clean after the wave-1 rename of session 241).

These checks apply after the named wave only:

- After wave 3: `scripts/cli-smoke.sh 2>&1 | tee tmp/verify/join/smoke.log`
  must exit 0 and print `SMOKE OK`.

  `STRIA_HOME=$(mktemp -d) swift run stria-app`, or "not run: headless".
